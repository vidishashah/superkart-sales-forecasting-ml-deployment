# SuperKart Sales Forecasting and ML Deployment

## Project Overview

Accurate sales forecasting is critical for retail businesses because it supports inventory planning, regional strategy, supply-chain decisions, and operational efficiency.

SuperKart is a retail chain operating supermarkets and food marts across multiple city tiers. The company wants to forecast product-store sales revenue for the upcoming quarter and use these predictions to support better inventory and sales planning.

This project develops an **end-to-end machine learning regression solution** that includes:

- Exploratory Data Analysis
- Feature Engineering
- Data Preprocessing
- Regression Modeling
- Hyperparameter Tuning
- Model Comparison
- Model Serialization
- Flask API Development
- Docker Deployment
- Streamlit Frontend Development
- Hugging Face Spaces Deployment

The final solution demonstrates not only model development but also how a trained machine learning pipeline can be packaged and served through a production-style application architecture.

---

## Business Objective

The goal of this project is to help SuperKart:

- Forecast product-store sales revenue
- Improve inventory planning
- Support regional sales strategy
- Understand the major factors influencing sales
- Compare machine learning models for forecasting
- Deploy the final model as a reusable prediction service
- Make predictions available through a user-facing application

---

## Machine Learning Problem

This is a **regression problem**.

The target variable is:

`Product_Store_Sales_Total`

The objective is to predict the total sales revenue generated by a specific product in a specific store.

```text
Product + Store Attributes
          ↓
Machine Learning Model
          ↓
Predicted Sales Revenue
```

---

The dataset contains product-level and store-level attributes.

| Feature | Description |

| `Store_Size` | Store size category |
| `Store_Location_City_Type` | City tier |

## Model Development

- XGBoost

The selected models were trained and evaluated using the chosen regression metric.

---

## Model Evaluation

Model performance was assessed using regression metrics including:

- R²
- RMSE
- MAPE

### R²

R² measures how much of the variance in sales is explained by the model.

### RMSE

RMSE measures the typical prediction error in the same units as the target variable.

### MAPE

MAPE measures average percentage prediction error.

These metrics provide complementary views of model performance.

---

## Hyperparameter Tuning

Hyperparameter tuning was performed on the candidate models to improve predictive performance.

The tuning process explored different parameter configurations and selected the strongest model based on validation performance.

This helped improve:

- Model accuracy
- Generalization
- Stability
- Prediction quality

---

## Model Comparison

All trained and tuned models were compared using the selected regression metrics.

The final model was chosen based on its balance of:

- Predictive performance
- Generalization
- Stability
- Business usefulness

The selected model was then evaluated on the test dataset.

---

## Model Performance

The final model achieved approximately:

- **R²:** 0.66–0.68
- **RMSE:** 600–620
- **MAPE:** 16–19%

These results indicate that the model captures meaningful sales patterns and can support broad forecasting and planning decisions.

The model is most appropriate as a **decision-support tool** rather than as the sole source for precise product-level inventory decisions.

---

## Model Serialization

The final trained preprocessing-and-model pipeline was serialized using `joblib`.

```text
Training Data
     ↓
Preprocessing + Model Pipeline
     ↓
Serialized Model
     ↓
Saved Model File
```

The serialized pipeline can later be loaded without retraining the model.

This enables consistent predictions in deployed applications.

---

## Prediction Workflow

The serialized model is loaded and used to generate predictions on new inputs.

```text
New Product / Store Data
          ↓
Serialized ML Pipeline
          ↓
Preprocessing
          ↓
Regression Model
          ↓
Predicted Sales
```

Because preprocessing and modeling are packaged together, the inference workflow remains consistent with training.

# Deployment Architecture

The final model was deployed using a client-server architecture.

```text
User Input
     ↓
Streamlit Frontend
     ↓
Flask REST API
     ↓
Serialized ML Pipeline
     ↓
Sales Prediction
     ↓
JSON Response
     ↓
Displayed to User
```

This architecture separates the user interface from model-serving logic.

---

## Flask Backend

A **Flask API** was developed to expose the trained model as a prediction service.

The backend:

- Accepts product and store attributes
- Loads the serialized ML pipeline
- Generates sales predictions
- Returns the result as JSON

The prediction endpoint follows the pattern:

```text
POST /v1/predict
```

This allows external applications to interact with the model through a standard HTTP interface.

---

## Docker Deployment

The Flask API was packaged using Docker.

The deployment setup included:

- Flask application
- Serialized model
- Python dependencies
- Dockerfile

The Dockerized backend was deployed to a **Hugging Face Docker Space**.

This makes the model-serving layer portable and reproducible.

---

## Streamlit Frontend

A **Streamlit web application** was developed as the user interface.

The frontend allows users to enter:

- Product details
- Pricing information
- Store characteristics
- Location information

The application sends these inputs to the Flask API and displays the predicted sales value.

The Streamlit application was deployed using a **Hugging Face Space**.

# Business Insights

## 1. Product MRP Is a Major Sales Driver

Product MRP showed the strongest relationship with sales.

### Business Implication

Pricing strategy has a significant impact on revenue.

SuperKart should evaluate price bands and optimize pricing rather than applying uniform pricing changes across products.

---

## 2. Store Characteristics Influence Revenue

Larger stores and certain store formats consistently generated higher sales.

### Business Implication

Expansion and investment decisions should consider historically high-performing store formats and locations.

---

## 3. Location Matters

Tier 1 and Tier 2 cities contributed significantly to overall sales.

### Business Implication

Inventory and product allocation can be adjusted based on regional demand.

Higher-demand markets may support:

- Greater inventory levels
- Broader product variety
- Premium product assortment

---

## 4. Product Visibility Influences Sales

Allocated product display area was associated with sales performance.

### Business Implication

Shelf placement and product visibility can be optimized for high-value products.

---

## 5. Product Category Affects Revenue

Some product categories contribute more strongly to overall revenue.

### Business Implication

Store assortment and inventory allocation should reflect category-level demand patterns.

---

# Business Recommendations

## Recommendation 1 — Use the Model for Directional Forecasting

The model captures approximately two-thirds of observed sales variation.

It can support:

- Sales planning
- Inventory strategy
- Regional comparisons
- Store-level forecasting
- Product-category analysis

It should be used as a decision-support tool rather than as the sole input for highly granular inventory decisions.

---

## Recommendation 2 — Optimize Pricing Strategy

Because Product MRP is strongly associated with sales:

- Analyze price bands
- Conduct pricing experiments
- Compare demand and margin trade-offs
- Avoid assuming that higher prices always increase total revenue

---

## Recommendation 3 — Allocate Inventory by Store and Location

Inventory planning should consider:

- Store type
- Store size
- City tier
- Product category

Higher-performing locations can receive greater stock allocations and broader assortments.

---

## Recommendation 4 — Improve Product Placement

Product visibility influences sales performance.

SuperKart can use historical sales data to determine which products should receive premium shelf placement.

---

## Recommendation 5 — Use Deployment as a Planning Tool

The deployed application can allow business teams to evaluate predicted sales for different product-store combinations.

This can support:

- Scenario planning
- Inventory discussions
- Regional planning
- Sales strategy evaluation
